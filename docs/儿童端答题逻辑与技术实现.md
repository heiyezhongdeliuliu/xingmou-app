## 0. 架构总览与脚本加载顺序

儿童端答题逻辑由多个 JS 文件通过**函数重写（monkey-patch）**层层包裹而成。加载顺序决定最终生效版本，完整顺序见 [index.html:100-131](../QizhiTrainingPlatform-Portable/index.html#L100-L131)。

关键重写链（后加载者包裹先加载者，最外层最后生效）：

```
renderTrain（最终）
  └─ level-curriculum.js      ← 儿童角色：20 关地图（最外层）
       └─ rubric-alignment.js ← 兴趣 gateway + 每日选择
            └─ question-logic-v2.js ← 六域冒险（22 模块）
                 └─ onboarding-assessment.js ← 专业端模块视图 + baseline 触发

openTrainer（最终）
  └─ rubric-alignment.js      ← 关卡解锁 + 积分奖励（最外层）
       └─ question-logic-v2.js ← 统一题型训练器（22 模块，含 trainingGate）
            └─ profile-agent.js   ← Agent 个性化题训练器
                 └─ safety-governance.js ← 安全门
                      └─ training.js ← 旧三大模块（attention/memory/logic）

runBaselineGames
  └─ baseline-logic-v2.js     ← v2（分级提示、准确计时）覆盖 v1

genPlan
  └─ question-logic-v2.js     ← 扩展 moduleDifficulty / domainStats
       └─ ai.js               ← 基础启发式方案生成
```

## 链路 A：首次评估（彩虹岛起点评估）

**触发**：儿童登录进入主界面后，`enterApp` 被 [onboarding-assessment.js:31-39](../QizhiTrainingPlatform-Portable/js/onboarding-assessment.js#L31-L39) 包裹，检测该儿童无已完成评估记录（`getBaselineRecord` 为空）时，120ms 延迟自动弹出评估。

### A1. 题目与结构
- 题源：`BASELINE_GAMES`（[onboarding-assessment.js:8-27](../QizhiTrainingPlatform-Portable/js/onboarding-assessment.js#L8-L27)），**24 题 = 6 领域 × 4 题**。
- 每题携带 `domain`（A–F）、`construct`（所测构念）、`basis`（依据来源，如"发育/智力评估""孤独症相关""行为观察"）。
- 无标准化量表：注释明确"不是 Gesell/WISC/Vineland/VB-MAPP/PEP-3/CARS"，只生成"平台训练起点画像"。

### A2. 答题流程（v2 版，[baseline-logic-v2.js:2-17](../QizhiTrainingPlatform-Portable/js/baseline-logic-v2.js#L2-L17)）
1. 选项通过 `shuffledQuestionChoices` 打乱（难度固定 3，即最多 3 个选项）。
2. **记忆类**（`preview` 存在）先显示 1.8s 再隐藏，再启用选项。
3. **计时**：`startedAt = performance.now()`；"再听一遍"期间记录 `pauseAt/pausedMs`，最终 `reactionMs = now - startedAt - pausedMs`，确保反应时不包含听题时间。
4. **分级提示**：`repeatCount++`（🔊 再听）、`hintCount++`（💡 禁用 1 个错误选项）。
5. **判定**：观察型（`responseMode==='observed'`）判 `picked !== '还没完成'`，其余判 `picked === target`。

### A3. 单题记录字段（[baseline-logic-v2.js:10](../QizhiTrainingPlatform-Portable/js/baseline-logic-v2.js#L10)）
```
id, childId, domain, gameTitle, construct, basis,
correct, firstCorrect (=correct && promptLevel===0),
promptLevel, repeatCount, hintCount, supportOutcome,
responseTimeMs, responseTimeContext, ts
```

### A4. 完成 → 画像生成（[onboarding-assessment.js:113-140](../QizhiTrainingPlatform-Portable/js/onboarding-assessment.js#L113-L140)）
```
finishBaselineJourney
  1) scoreBaselineDomainV2(answers)        → 六域 0–100 分
  2) buildIntegratedProfile(childId,...)   → 多来源证据分层
  3) child.profile6 = scores               → 旧三维兼容字段回填
  4) baselineAssessment 写入 enhancedState.assessments
  5) baselineRecords 写入 records + backendSaveTrainingRecords
  6) plans[childId] = genPlan(childId)     → 首版难度方案
  7) dbSaveAbilityProfile(profile)         → 画像写库（status=current）
  8) generateChildProfileNarrative(scores) → Ollama 改写鼓励文案
  9) profile.narrative / aiProvider / aiModel 回填
  10) dbSaveAiInference(...)               → AI 推理审计
  11) backendSaveProfileBundle(...)        → 同步 SQLite
  12) 渲染"彩虹画像"卡片 + 进入训练地图
```

## 链路 B：20 关彩虹冒险地图（日常训练主界面）

儿童角色的 `renderTrain` 最终由 [level-curriculum.js:148-159](../QizhiTrainingPlatform-Portable/js/level-curriculum.js#L148-L159) 接管。

### B1. 地图渲染
- 若无画像 → 提示"先完成彩虹岛小游戏 🌈"。
- 显示 20 关 `CURRICULUM_LEVEL_TITLES`（[level-curriculum.js:9](../QizhiTrainingPlatform-Portable/js/level-curriculum.js#L9)），每关 5 个小游戏（activity）。
- 每关 `theme` 取自焦点领域名 + "岛"，`difficulty = min(5, floor(index/5)+1)`。

### B2. 关卡生成（两路 + 兜底）
- **后端 Agent 路**：`fetchPersonalizedCurriculum` → `/api/personalized/levels`（CrewAI + qwen3:0.6b），拿到则 `registerCurriculumLevels` 追加到本地地图。
- **本地规则路**：`buildLocalCurriculum`（[level-curriculum.js:24-41](../QizhiTrainingPlatform-Portable/js/level-curriculum.js#L24-L41)）：
  - 领域顺序 `curriculumDomainOrder` = 按画像分数**从低到高**排序（先练弱项）。
  - 每关取 3 个焦点领域（`order[i%6], order[(i+1)%6], order[(i+3)%6]`）。
  - 从 `TRAINING_CATALOG` 选 5 个不重复 activity，尊重儿童"不想玩"排除项。
  - 标记 `generatedBy: {provider:'browser-safe-fallback', model:'rules-v1', fallback:true}`。

### B3. 关卡内答题 `runCurriculumQuestions`（[level-curriculum.js:121-146](../QizhiTrainingPlatform-Portable/js/level-curriculum.js#L121-L146)）
- 每题来源 `curriculumQuestions`：**远程 Agent 题 > 本地 `MODULE_ACTIVITY_BANK`**（按 `questionVariant` 轮换变体）。
- 记忆题 `preview` 1.8s 后显示选项；音频题 TTS 朗读。
- 选项数随难度（`shuffledQuestionChoices`）。
- 记录含 `curriculumLevelId`、`curriculumRunId`（整关一次运行）。
- 通过判定：`passed = 完成数 ≥ minCompleted(5) 且 正确率 ≥ minAccuracy(0.6)`（[level-curriculum.js:62-70](../QizhiTrainingPlatform-Portable/js/level-curriculum.js#L62-L70)）。

## 链路 C：单模块训练器（openTrainer 重写链）

`openTrainer` 是统一训练入口，被 4 层重写。**儿童端通过 20 关地图间接复用其底层题型引擎；家长/专业端直接调用。**

### C1. 最外层：积分奖励（rubric-alignment.js:57-67）
```
检查 rubricCanOpenLevel（关卡解锁）
  → 记录训练前 record IDs（beforeIds）
  → 完成回调里 diff 新增记录 → recordRubricReward（+10 积分）
```

### C2. 统一题型训练器（question-logic-v2.js:76-85）
- `!MODULE_ACTIVITY_BANK[moduleId]` → 回退旧三大模块。
- `trainingGate` 拦截后，拉取 Agent 题 + 本地题去重合并，取前 3 题。
- 调用 `openUnifiedQuestionTrainer`。

### C3. Agent 个性化题训练器（profile-agent.js:13-21）
- 模块在 22 目录内且**有 Agent 题** → `openAgentQuestionTrainer`（[profile-agent.js:23-53](../QizhiTrainingPlatform-Portable/js/profile-agent.js#L23-L53)），否则回退。

### C4. 安全门（safety-governance.js:54-62）
- `trainingGate` 通过后进入 `governedOpenTrainer`。

### C5. 旧三大模块（training.js:30-55）
- `attention` → `playAttention`（5 轮网格找目标，网格 4/9 随难度）。
- `memory` → `playMemory`（翻牌配对，对数随难度 3/4/6/8/10）。
- `logic` → `playLogic`（找不同，5 轮，diff≥4 加入近似色干扰）。

### C6. 统一训练器核心 `openUnifiedQuestionTrainer`（question-logic-v2.js:87-113）
- 每轮 3 题，`updateDifficulty` 实时调难度。
- 观察型判定：`correct = (mode==='spoken'||'guided') ? completed : picked===target`。
- `promptLevel` 判定：hint→2、repeat→1、帮助后完成→2、独立→0。

## 链路 D：计分与评分

### D1. 提示分级（promptLevel / supportOutcome）
| 值 | promptLevel | supportOutcome |
|---|---|---|
| 独立首答正确 | 0 | independent |
| 重复听后再对 | 1 | independent |
| 用提示后对 | 2 | independent |
| 帮助后完成 | 2 | supported |
| 未完成 | — | not-completed |

### D2. 六域加权评分 `scoreBaselineDomainV2`（question-logic-v2.js:115-119）
```
错误            → 0
帮助后完成      → 0.5
用了提示后对    → 0.55
重复听后再对    → 0.8
独立完成        → 1
score = round(sum / 题数 * 100)
```

### D3. 多来源证据分层 `buildIntegratedProfile`（assessment-framework.js:28）
- **证据优先级**：专业评估/人工确认 > 多次训练趋势 > 家庭多场景观察 > 单次表现。
- 分层但不混合：平台游戏分、专业量表结果（近 1 年内）、家长观察（近 30 日）各自独立呈现，`weights: null`。

## 链路 E：自适应难度

### E1. 实时（题内）`makeAdaptive` / `updateDifficulty`
> 连续 2 次独立答对 → 升 1 档；连续 2 次错 → 降 1 档；区间 1–5。
- 旧模块实现：[training.js:66-75](../QizhiTrainingPlatform-Portable/js/training.js#L66-L75)
- 统一题型实现：[question-logic-v2.js:93](../QizhiTrainingPlatform-Portable/js/question-logic-v2.js#L93)

### E2. 进入前（题间）`moduleDifficultyFor`（question-logic-v2.js:43-54）
优先级从高到低：
```
① 已实名签署方案的指定难度（effectiveClinicalPlan）
② 已复核方案的难度（currentPlanReview.status==='effective'）
③ 画像起点：ceil(score/22) 取整，封顶 4
④ 最近 6 题加权：独立=1 / 答对=0.65 → 加权≥0.8 升、<0.45 降
```

### E3. 选项数量随难度（shuffledQuestionChoices）
难度 1 → 2 项；难度 2 → 3 项；难度 ≥3 → 全部。

## 链路 H：兴趣入口与积分奖励

### H1. 每日兴趣选择（rubric-alignment.js:6-10, 82-103）
- 3 个兴趣频道：`color`（颜色世界）、`shape`（图形乐园）、`sound`（声音森林），映射到不同模块。
- 每天首次进入训练地图弹"今天想玩什么？"，选择后记录 `recordRubricInterest` + `saveRubricDailyChoice`。
- 选中频道内的关卡置顶为"兴趣链"，其余降暗。

### H2. 积分奖励 `recordRubricReward`（rubric-alignment.js:31-41）
- **完成一轮 +10 积分**，按"完成/坚持"发，不按答对数。
- 幂等：通过 `recordIds` 对比，同一批记录不重复发。
- 50 积分 = 1 徽章（`rubricRewardSummary`）。

### H3. 兴趣与能力分开解读（rubric-alignment.js:105-115）
- 兴趣来自主动选择次数；能力来自首答正确率/反应时/提示次数。
- 明确提示"兴趣高 ≠ 能力高"。

## 链路 I：安全门 `trainingGate`（答题前强制拦截）

顺序（[safety-governance.js:35-53](../QizhiTrainingPlatform-Portable/js/safety-governance.js#L35-L53)）：

1. **数据授权**：`dbCanAccessChild` 校验账号与儿童绑定。
2. **安全暂停**：`activeSafetyRisks` 有 active 标记（癫痫/自伤/攻击/情绪爆发/吞咽/跌倒）→ 拦截。
3. **知情同意**：儿童/家长角色需家长已勾选 `training` scope。
4. **已签署方案**：儿童/家长必须有实名签署的方案，且该模块在方案内（`isModuleInEffectivePlan`）。
5. **线下模块拦截**：`OFFLINE_MODULES = {D03:'offline', D02/D01/S02/S03/L02:'hybrid'}`（safety-governance.js:9-13），offline 模块转为线下记录。

## 链路 K：画像闭环（答题 → 难度 → 画像）

```
每次训练 finish
  → records 合并 + backendSaveTrainingRecords
  → plans[childId] = genPlan(childId)   ← 重算六域难度（moduleDifficulty + domainStats）

  → 达到目标 → 结案/转段（clinical-workflow renderClosureFollowup）
```
